# 1. ВВЕДЕНИЕ

Современный мир невозможно представить без обмена информацией. Файловые хранилища и сервисы для обмена файлами стали неотъемлемой частью повседневной жизни как обычных пользователей, так и бизнеса. Облачные технологии позволяют хранить большие объёмы данных, обеспечивая доступ к ним из любой точки мира с любого устройства.

В данной выпускной квалификационной работе разрабатывается веб-приложение «DropFilesKgpk» — система для безопасного обмена файлами между пользователями с возможностью авторизации, создания папок, генерации ссылок для скачивания и публичного доступа к файлам.

**Целью работы** является создание полнофункционального веб-приложения для обмена файлами, которое обеспечивает:

- Регистрацию и аутентификацию пользователей
- Загрузку и скачивание файлов
- Организацию файлов в папки
- Генерацию ссылок для общего доступа
- Публичную ленту файлов
- Адаптивный интерфейс для любых устройств

**Задачи работы:**

1. Провести анализ предметной области и существующих решений
2. Спроектировать архитектуру приложения и базу данных
3. Реализовать функциональность на выбранном стеке технологий
4. Разработать удобный пользовательский интерфейс
5. Провести тестирование приложения

# 2. АНАЛИТИЧЕСКАЯ ЧАСТЬ

## 2.1. Постановка задачи

Требуется разработать веб-приложение «DropFilesKgpk» со следующими функциональными требованиями:

| № | Требование | Описание |
|---|------------|----------|
| 1 | Регистрация/вход | Создание аккаунта с email и паролем |
| 2 | Загрузка файлов | Загрузка файлов любого формата на сервер |
| 3 | Папки | Создание, переименование, удаление папок |
| 4 | Личные файлы | Приватный доступ только для владельца |
| 5 | Ссылки для скачивания | Генерация уникальной ссылки для общего доступа |
| 6 | Публичные файлы | Возможность сделать файл публичным |
| 7 | Публичная лента | Просмотр всех публичных файлов пользователей |
| 8 | Лимит хранилища | Ограничение объёма хранимых данных |

## 2.2. Описание предметной области

Область разработки относится к системам управления файлами (File Management Systems) и сервисам обмена файлами (File Sharing Services). Подобные системы широко используются в образовательных учреждениях, бизнесе и повседневной жизни.

Основные участники системы:

- **Обычный пользователь** — загружает файлы, создаёт папки, делится ссылками
- **Администратор** — имеет доступ к управлению пользователями и файлами

Основные сущности системы:

- Пользователь (User)
- Файл (File)
- Папка (Folder)
- Ссылка для скачивания (ShareLink)

## 2.3. Обзор аналогичных решений

На рынке существует множество аналогичных решений:

| Сервис | Особенности | Недостатки |
|--------|-------------|------------|
| Google Drive | 15 ГБ бесплатно, интеграция с Google | Требует Google аккаунт |
| Dropbox | Простота, синхронизация | Ограниченное бесплатное хранилище |
| Яндекс.Диск | Русский язык, 10 ГБ | Привязка к Яндексу |
| Облако Mail.ru | 100 ГБ | Требует аккаунт Mail.ru |

**Преимущества разрабатываемого решения:**

- Открытый исходный код
- Возможность развёртывания на собственном сервере
- Отсутствие привязки к сторонним сервисам
- Простота и понятность интерфейса

Приложение построено по принципу **клиент-серверной архитектуры** с использованием современного веб-фреймворка Next.js.

```

└─────────────────────┬───────────────────────────────┘
                      │ HTTP/REST API
┌─────────────────────┴───────────────────────────────┐
│                   Сервер (Vercel)                    │
│                  Next.js App Router                  │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐   │
│  │  Auth API   │ │  Files API  │ │ Folders API │   │
│  └─────────────┘ └─────────────┘ └─────────────┘   │
└─────────────────────┬───────────────────────────────┘
                      │
┌─────────────────────┴───────────────────────────────┐

                      │
```

## 3.2. Проектирование базы данных

Используется СУБД **PostgreSQL** с ORM **Prisma**. Логическая модель данных:

### User (Пользователь)

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID | Уникальный идентификатор |
| email | String | Email (уникальный) |
| passwordHash | String | Хэш пароля |
| name | String | Имя пользователя |
| role | Enum | Роль: USER, ADMIN |
| storageLimit | BigInt | Лимит хранилища (по умолчанию 1 ГБ) |
| createdAt | DateTime | Дата создания |

### File (Файл)

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID | Уникальный идентификатор |
| originalName | String | Оригинальное имя файла |
| storedName | String | Уникальное имя в хранилище |
| mimeType | String | MIME-тип файла |
| size | BigInt | Размер в байтах |
| userId | UUID | Владелец файла |
| folderId | UUID? | Родительская папка |
| accessType | Enum | PRIVATE, LINK_ACCESS, PUBLIC |
| createdAt | DateTime | Дата загрузки |

### Folder (Папка)

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID | Уникальный идентификатор |
| name | String | Название папки |
| userId | UUID | Владелец папки |
| parentId | UUID? | Родительская папка |

### ShareLink (Ссылка для скачивания)

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID | Уникальный идентификатор |
| token | String | Уникальный токен ссылки |
| fileId | UUID | Ссылаемый файл |
| expiresAt | DateTime? | Срок действия |
| downloads | Int | Количество скачиваний |

## 4.2. Основные модули и их функции

### Аутентификация (/src/lib/auth.ts)

Модуль отвечает за регистрацию, вход и управление сессиями пользователей. Использует NextAuth.js с провайдером учётных данных (Credentials).

```typescript
// Пример: проверка аутентификации
const session = await auth();
if (!session?.user) {
  return NextResponse.json({ error: "Не авторизован" }, { status: 401 });
}
```

### Загрузка файлов (/src/app/api/files/upload/route.ts)

Обрабатывает загрузку файлов через multipart/form-data:

1. Принимает файл от клиента
2. Проверяет размер и квоту хранилища
3. Генерирует уникальное имя файла
4. Загружает в Supabase Storage
5. Создаёт запись в базе данных

### Скачивание файлов (/src/app/api/files/[id]/download/route.ts)

Обрабатывает скачивание файлов:

1. Проверяет доступ (приватный/по ссылке/публичный)
2. Получает файл из хранилища
3. Возвращает с правильными заголовками Content-Disposition

### Управление папками (/src/app/api/folders/route.ts)

CRUD-операции для папок:

- GET — список папок
- POST — создание папки
- PATCH — переименование
- DELETE — удаление

### schema.prisma (схема базы данных)

```prisma
model User {
  id            String    @id @default(uuid())
  email         String    @unique
  passwordHash  String
  name          String    @default("")

  storageLimit  BigInt    @default(1073741824)

model File {
  id          String      @id @default(uuid())
  originalName String
  storedName  String      @unique
  mimeType    String
  size        BigInt
  userId      String
  user        User        @relation(fields: [userId], references: [id])
  folderId    String?
  accessType  AccessType  @default(PRIVATE)
}
```
